# 2026-08-20 参加会計金額0円事象の調査

対象は、2026-08-20 19:00–21:00 の一般レッスンに参加した梶本実津夫さんの予約である。コード調査では原因を一意に確定できず、本番の対象予約1件の証拠確認が必要と判断した。

最も直接的な表示原因は、`lesson_member_list.py` が `participant_ticket_price_snapshot=None`（価格未確定）を `or 0` で0円表示することにある。購入証拠がない予約では `consume_tickets()` が `purchase=None` / `unit_price_snapshot=None` の消費行を作り、価格スナップショットを確定しないため、無料チケットを付与していなくても0円表示になり得る。後日の手動変更は保存値を3,500円へ上書きするため、現在値だけでは元が `None` と0のどちらだったか判定できない。

実値0の経路もある。管理調整フォームは0円を許可して `purchase_type=admin` のロットを作成でき、`formal_free` は0円を必須とする。モデルと共通購入サービス自体には種別と価格の組合せ制約がないため、コード呼出しでは `single`、`set4`、`event`、`legacy` も0円にできる。ただし現行の通常有料フォームは0円を拒否し、`event` / `legacy` の現行作成UIやデータmigrationは確認されなかった。後購入割当は種別を限定せずFIFOで購入ロットの価格を転記するため、0円ロットなら予約価格も0円で確定する。

対象予約の `ParticipantPriceChange` 履歴、`TicketConsumption`、紐づく `TicketPurchase` を確認すれば、(1) 未確定値の0円表示、(2) 0円ロット由来、(3) コーチによる0円手動設定、のどれかを判別できる。詳細な限定Django shell手順はリポジトリルートの `report.md` に記載した。
