# チケット負担変更

## データの役割

- `Reservation.user` は参加者アカウント（家族参加では保護者）を表す。
- `Reservation.tickets_used` は、その参加者に本来必要な枚数を表し、負担変更では更新しない。
- 未返却の `TicketConsumption.user` は、その予約を現在負担しているアカウントを表す。
- `TicketBurdenChange` は旧負担者、新負担者、枚数、操作者を保存する正式な変更履歴である。

## 変更処理

メインコーチだけがメンバーリストから変更できる。サービスは同一レッスンのチケット対象予約をすべて受け取り、会計月が開いていることと既存消費証跡の整合を確認する。予約、利用者、購入ロットを固定順でロックし、旧負担者への返却、新負担者からのFIFO消費、台帳、変更履歴を1トランザクションで保存する。同じ内容の再保存は何も変更しない。

キャンセル・雨天中止では、未返却の消費証跡を負担者別に集計して実負担者へ返却する。診断は `TicketBurdenChange` に裏付けられたcross-payerのみ正常として扱い、根拠のない不一致は従来どおり異常とする。

負担変更で新しい負担者に未使用の購入ロットがある場合は、購入日時順のFIFOでそのロットを先に割り当てる。購入ロットで説明できない残高だけを価格未確定の消費証跡にする。これにより、同じ会員が他参加者分を負担した場合も、その会員が実際に購入した単価を参加者価格へ確定する。
